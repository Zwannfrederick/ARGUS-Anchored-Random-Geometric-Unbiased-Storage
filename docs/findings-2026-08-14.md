# Findings — 2026-08-14 stabilization pass

Work stopped mid-Task 16 at the user's request. This records what was
measured, what it means, and what is still open. Nothing here is estimated.

---

## 1. The headline: ARGUS currently costs more than it saves at every context measured

`docs/measurements/downstream-2026-08-14.json` (claim class: `downstream`).
Qwen2.5-0.5B-Instruct, RTX 3050 Ti Laptop 4 GB, page_size 256, 2 repeats,
16 generated tokens, median reported.

| context | arm | TTFT (s) | TPOT (ms) | peak VRAM (MiB) |
|---:|---|---:|---:|---:|
| 8192 | baseline | 0.810 | 17.94 | 1340.4 |
| 8192 | **argus** | **2.553** | **30.10** | **1564.3** |
| 16384 | baseline | 1.785 | 18.68 | 2150.0 |
| 16384 | **argus** | **5.459** | **36.84** | **2567.1** |

ARGUS is **~3× slower to first token, ~2× slower per token, and uses ~17-19 %
*more* peak VRAM** than the plain HuggingFace cache. There is no crossover up
to 16K tokens on this hardware.

This directly contradicts the project's central claim ("prevents VRAM
allocation collapse"). At these sizes the KV cache is small relative to
ARGUS's own resident overhead — per-tier static pools, per layer, plus the
active pool — so the runtime pays for machinery it is not yet using.

**This does not prove ARGUS never helps.** It proves the benefit was never
demonstrated in the regime that was actually tested. The claim requires a
context length where the baseline OOMs and ARGUS does not; that point was not
reached here, because a 0.5B model on a 4 GB GPU fits 16K tokens comfortably.
Finding it needs a larger model or longer context, and until then the VRAM
claim is unsupported.

### A near-miss worth recording

An earlier run showed ARGUS OOMing at 8192 tokens where baseline survived.
That was **a defect in my benchmark harness, not in ARGUS**: it materialized
logits for every prefill position (`seq_len × vocab × 2 B` = 2.32 GiB at 8192
tokens) and died in the model's `lm_head`. Fixed with `logits_to_keep=1`.
Results taken before the fix were discarded rather than published next to the
corrected ones. Flagged because it is exactly the kind of artifact that would
have been published as a dramatic finding.

### Perplexity

| arm | perplexity | delta |
|---|---:|---:|
| baseline | 33.9169 | — |
| argus | 33.8372 | **−0.0797** |

Measured token-by-token *through the cache under test*, so the cache is
genuinely exercised — a batched scoring pass would bypass it entirely and
report a meaningless zero. Verified by recording tier occupancy during
scoring: `{active: 24, fp8: 24}`.

**Caveat that matters:** only fp8 (2×, near-lossless) was reached at this
passage length. The deeper lossy tiers — int4, int2, one_bit — were **not
exercised**, so this delta says nothing about them. A near-zero perplexity
delta from an fp8-only cascade is close to a tautology.

## 2. The JL tier is justified — and was justified for the wrong reason

`docs/measurements/jl-2026-08-14.json` (claim class: `reconstruction`).

| result | value |
|---|---|
| JL median rel. L2 | **0.413** |
| int2 as shipped (equal 4× budget) | 0.565 |
| JL beats shipped int2 | **20 / 24 layers** |

The tier earns its slot against the real competitor, not a strawman.

The documentation justified it by "the low-rank structure of real KV tensors".
**That reasoning is wrong.** The operator carries a *smoothness* prior — a 1-D
Laplacian along the sequence axis — not a low-rank one, and it recovers a
rank-4 random signal no better than white noise (1.106 vs 1.111, measured).
What it actually exploits is token-to-token smoothness: reconstruction error
tracks page roughness at **r = 0.988**, and all four losing layers are the four
roughest. A test now asserts the disproved premise so the framing cannot drift
back.

## 3. Defects found and fixed

| defect | consequence | status |
|---|---|---|
| Unbounded tier (`max_pages=-1`) passed the sentinel to `torch.zeros` | "Dimension size must be non-negative" — any pipeline with an archival tier died | fixed; pre-existing, the name-branch code had no guard either |
| sdist shipped `.cpp`/`.cu` but not the `.h` headers they include | install from tarball failed at `fatal error: manager.h` — every prior release had this | fixed via `MANIFEST.in` |
| Root `models/attention_wrapper.py` was a divergent copy | 121 lines behind; silently dropped `pipeline=` and `balloon_driver=` | fixed; test forbids re-implementing shims |
| Prefetch worker cached undefined tensors for projection pages | surfaced later as an empty page during attention | fixed |

## 4. Verified against reality

- **Ollama adapter** — 5 live tests against Ollama 0.32.11 / `qwen2.5:0.5b`.
  Adapter needed no changes. Median 264 tok/s, `docs/measurements/ollama-2026-08-14.json`.
  Labelled **external**: ARGUS does not manage that KV cache.
- **v0.3.0 artifact** — builds, passes `twine check`, and installs into a fresh
  venv outside the repo, compiling against torch 2.13 (not only the pinned
  2.12). Tagged locally, **not pushed, not uploaded**.
- **Test suite** — 191 passed, 1 skipped (vLLM absent), from 72 at the start.
