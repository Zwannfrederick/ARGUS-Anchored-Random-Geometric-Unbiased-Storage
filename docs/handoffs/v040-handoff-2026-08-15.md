## Completed implementation

- Native GGML-compatible `q8_0` and `q4_0` ARGUS codecs are in main commit
  `3258af5`. They have exact block-layout tests, FP32 range guards, launch
  checks, and safe mapped-host buffer lifetime handling.
- The llama.cpp fork exposes an opt-in hybrid ownership probe:
  `LLAMA_ARGUS_HYBRID_PROBE=1` reports attention-KV and recurrent-state bytes
  separately. It does not alter the stock cache or graph path.
- Main commit `77e3a3e` adds a registry-only Llama full-attention adapter.
  It shares the narrow eval/unmasked/single-token GQA contract with Qwen2,
  rejects unsupported semantics through fallback, and has CPU SDPA parity plus
  tiny Transformers generation coverage.

## Active blocker: NVIDIA driver

At handoff, both `nvidia-smi` and PyTorch CUDA were unavailable:

```text
nvidia-smi: couldn't communicate with the NVIDIA driver
torch.cuda.is_available(): False
```

The full suite consequently is not a valid release signal in this state:
`72 failed, 137 passed, 25 skipped`. The failures are CUDA-native cache tests
receiving CPU tensors; do not relabel this as a code regression or weaken the
tests to skip it silently. An earlier healthy-driver run was `231 passed,
1 skipped` before the driver dropped.

RAM had recovered to about 18 GiB available. Swap remains populated from the
earlier accidental model metadata invocation; a reboot clears both the driver
state and stale swap pressure. Do not repeat `llama-gguf r n` or any command
that opens the 27B artifact merely to read metadata.

```bash
TORCH_CUDA_ARCH_LIST=8.6 .venv/bin/python setup.py build_ext --inplace
.venv/bin/python -m pytest -q
```

Only if both suite runs are green, record the S1 gate artifact. Then rebuild
the fork without loading the model for unrelated metadata work:


When a deliberate Qwen3.8 context run is authorized, set
`LLAMA_ARGUS_HYBRID_PROBE=1` and capture separate attention/recurrent byte
totals. The model must be loaded only for an explicit measurement/generation
run, never for casual inspection.
