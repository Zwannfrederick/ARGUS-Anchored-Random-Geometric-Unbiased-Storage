# v0.6: D=64 specialized resident batched kernel (4K)

Same workload and budgets as [the datapath report](v060-datapath-2026-09-18.md);
placement policy unchanged; output hash unchanged
(`a152ed5676e2f9f4412d7aadffa7054cc438c021549ecb4f472a83c864acba0a`).

## Change

`attention_resident_batch<D>`: for Dk = Dv = 64 the register arrays hold D/32
slots instead of eight and the unused unrolled slots disappear. The generic
kernel (`D = 0`, e.g. D=48, D=256, Dk != Dv) is unchanged. The reduction tree is the
staged 256-lane stride-halving tree; the specialization only omits additions of
the tree's structural +0 slots, which can change nothing but the sign of an
all-zero sum (and `-0 == +0` in the exact float gate).

The score, running-sum and value accumulations are now written as the explicit
`__fmaf_rn`/`__fmul_rn` forms NVCC had already emitted. SASS of the staged kernel
and of the generic batched kernel is instruction-for-instruction identical to
`7c51892` (normalized `cuobjdump -sass` diff: 0 lines).

| Kernel | Registers | SASS instructions | Blocks/SM (128 threads) | Waves at 224 blocks |
|---|---:|---:|---:|---:|
| generic (before, still used for D != 64) | 52 | 1016 | 9 | 1.24 |
| D=64 | 38 | 688 | 12 | 0.93 |

## Correctness

New Qwen-geometry case in `tests/cpp/test_ggml_cuda_mechanism.cpp`: 14 Q / 2 KV
heads, D=64, 64 causal query tokens, 500 cells: staged, direct and batched must be
float-vector equal. A deliberate mutation of the D=64 value FMA order was caught
(1-ulp mismatch). GPU tests `5 passed`, CPU/context tests `5 passed`.

## Result: GPU-control, profiler disabled, 3 repeats each

| Binary | Prefill median (min–max) | Decode tok/s median |
|---|---:|---:|
| `7c51892` generic | 12.327 s (12.312–12.344) | 7.764 |

2.24x prefill speedup; the ranges do not overlap. Decode uses the unchanged staged
path (Q=1); its difference is not attributed to this change.

Holding occupancy fixed, the specialization alone gives 2.10x kernel time; the
extra occupancy / single wave gives a further 1.27x. The wave-quantization
hypothesis is confirmed but secondary: most of the gain comes from removing the
dead D-generic slots and their branch structure. The generic row comes from an
earlier session with the same kernel code, so that factor is approximate.
