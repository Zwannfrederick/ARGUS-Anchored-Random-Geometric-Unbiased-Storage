# v0.7 E1: coalesced K-row loads in the lane-per-cell kernel (4K) — ACCEPT

One causal factor changed: how the K rows of a 32-cell tile reach the lane that scores
them (`attention_resident_cells<true, true>`, `ARGUS_KV_ATTENTION_PATH=cells-kc`, now the
default). The tree, the score, the prefix max, the V loop, the unroll depth and the mask
handling are unchanged. Chosen from [Experiment 0](../../plans/argus-v0.7.0.md#experiment-0-result-nsight-compute-same-late-launch-cells-vs-cells-mlp).
Raw data: [`v070-e1-2026-09-19/`](v070-e1-2026-09-19/).

## Change and exactness (category 1)

The tree reads chunks `m, m+2, m+4, m+6` (16 bytes each) of a row in pass `m` = 0, 1.
Before this change, each lane loaded its own row: 8 `LDG.E.128` per lane per tile, with
lanes 256 B apart, which is 32 wavefronts per request. Now, in each pass:

1. Every lane obtains cell pointers by `__shfl_sync` from their owner lanes. Lanes `4s..4s+3` fetch one row's four
   chunks, 8 rows per warp load: 4 `LDG.E.128` per pass.
2. They store the chunks to a per-warp shared tile, swizzled as
   `4c + (r ^ (c/2 % 4))`.
3. `__syncwarp`, then each lane reads its own four chunks (`LDS.128`), then `__syncwarp`
   again before the next pass overwrites the tile.
4. The pass computes `half_sums[8m..8m+7]` with the same `__fmul_rn`/`__fadd_rn`
   expressions. The rest of the tree and `__fmaf_rn(dot, scale, bias)` run for live
   lanes only.

This deviates from the plan's sketch (8 lanes per full row). With full rows, a tile
would need a 4 KiB/warp buffer, or else only 8 lanes could score at a time. Masked
lanes publish a null row and run the arithmetic on zeros. That result is discarded, and
null pages still read as zero.

| kernel | registers | stack / spill | shared/block |
|---|---:|---:|---:|
| `cells-mlp` | 58 | 0 / 0 | 3 KiB |
| `cells-kc` | **66** | 0 / 0 | **11 KiB** |

- Other instantiations: SASS for staged, both batched, `cells` and `cells-mlp` is
  identical to before (normalized diff).
- `__launch_bounds__(128, 8)`: rejected. It caused 56 B of spill in kc and pushed the
  other instantiations to 85–86 registers.
- Splitting `half_sums` into two explicit arrays: needed, because otherwise it lived in
  a 64 B local frame.

**Correctness.**
- `cells-kc` is in every exact path list: the resident and mixed-residency loops at
  D = 48/64/256, shifted views and cold pages.
- It also runs all Qwen 14/2/D64 cases: causal, scattered −∞, fully masked tile and
  rows, live null pages, F32 bias, ×24 scores, ±0 with ties.
- Everything is bit-exact with staged.
- A mutation that permutes the K row assignment (`owner ^ 1`) fails.
- GPU `7 passed`, CPU/context `5 passed`, on the explicit path and again with
  `cells-kc` as the default.
- The output hash is `a152ed56…` in every run.

| 7 alternating pairs: prefill median (min–max) | 2.858 s (2.787–2.911) | **2.667 s** (2.614–2.929) | **−6.7%**; kc faster in 6/7 pairs |
| CUDA-event prefill kernel time, 3 pairs (profiled) | 1.314 s | **1.156 s** | **−12.0%** (spread ≤0.01 s) |
| policy-on kernel time, 3 pairs (profiled) | 1.667 s | 1.426 s | −14.5% |

Policy-on wall clock is dominated by disk noise. `cells-mlp` runs vary from 10.0 to
16.6 s, `cells-kc` runs from 9.9 to 12.1 s, with medians 10.04 vs 10.43 s over 3
repeats. No kernel-side regression. The 7-pair ranges overlap because of three slow kc
runs; the kernel-event gain is deterministic.

**Causal signature (measured).**
- **Confirmed:**
  - The K coalescing removed 58% of global data-pipe wavefronts.
  - Total data-pipe work fell 23% and its utilization fell 76 → 67%.
  - `lg_throttle` disappeared, long scoreboard fell 36%, the issue rate rose and the
    kernel is 12% shorter.
  - L1 hits rose despite L1 shrinking to 28 KB: fewer duplicate in-flight misses
    reach L2.
- **Weaker than the plan predicted:**
  - Wavefronts 35.9 M, not 25–30 M, and utilization 67%, not < 55%.
  - The transposed half-rows cost 8 global wavefronts per request instead of 4.
  - The shared round-trip costs 9.4 M wavefronts instead of ~7 M.
- **Costs paid:** 66 registers and 7 blocks/SM, and an L1 carveout of 28 KB. The net
  gain includes these costs.

## Verdict: ACCEPT

The plan's exception applies: occupancy is below 8 blocks/SM, and registers are > 64,
but with a measured net win.
- Bit-exact, with the hash unchanged.
- −6.7% GPU-control prefill (≥5%).
- −12% kernel time.
- The targeted L1TEX data-pipe pressure is measurably reduced.

`cells-kc` is the default; `cells-mlp`, `cells`, `batched`, `direct` and `staged` stay
selectable as references.

**New dominant bottleneck inside the kernel.** It is still the L1TEX data pipe, at 67%.
Now 60% of it is shared-memory wavefronts: 12.0 M from q/weight/pointer `LDS`, and
9.4 M from the K tile round-trip. `mio_throttle` (1.51) is now the largest throttle,
together with long scoreboard. At the macro level, attention (≈1.16 s of events) is
still the largest ARGUS component. The CPU-side page-write/verification path
(`set_rows` ≈0.66 s inclusive, profiled) is the second.
