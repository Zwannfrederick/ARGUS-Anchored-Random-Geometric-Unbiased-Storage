# v0.7 E4: V values as `half2` — ACCEPT, now the default

Candidate 1 of the post-E3 map. The only change is the V loop of `attention_resident_cells`: a lane owns output dims `2l` and `2l+1` instead of `l` and `l+32`, and loads both with one 32-bit `half2` `__ldg` instead of two 16-bit ones. Raw data: [`v070-e4-2026-09-25/`](v070-e4-2026-09-25/).

## Exactness: Category 1

Every output dim keeps its own `acc` chain. The chain advances cell by cell, in the same order, with the same `__fmaf_rn(w.x, acc, __fmul_rn(w.y, v))` and the same weights. `__half22float2` performs the same exact half→float conversion as two `__half2float` calls. `sum`, the scores, the prefix max and the mask handling are untouched. The only things that change are which lane holds a dim and the matching output index.

**Mutation checks.** Swapping `pair.x`/`pair.y`, and restoring the old output index for v2, each make `test_cuda_tier_migration_and_attention` fail. The unmutated code passes.

## SASS gate (`-arch=sm_86`, nvcc 13.3)

| | cells-kc | cells-v2 |
|---|---:|---:|
| V loads per unrolled 4-cell group | 8 `LDG.E.U16.CONSTANT` | 4 `LDG.E.CONSTANT` (32-bit) |
| instructions | 832 | 824 |
| registers | 66 | **76** |
| spill | 0 | 0 |
| blocks/SM (register-limited) | 7 | **6** |

The three reference instantiations (`cells`, `cells-mlp`, `cells-kc`) compile to SASS that is byte-identical to `be4cc47`. The first draft of this change used a shared lambda, which altered them (848→832 and 792→776/784 instructions), so the change was narrowed to the `v2` branch only. The register peak is not in the V loop: the V loop uses fewer registers than kc's (R25 vs R36). ptxas schedules the unchanged score phase differently.

**Occupancy, measured rather than assumed.** `__launch_bounds__(128, 7)` fits the kernel into 72 registers, but at the cost of 24 bytes of stack and one `LDL.64` per tile. Kernel events for that variant: **+1.3%, slower in 5/5**. It is rejected; do not retry it. The unbounded kernel, at 6 blocks/SM, is the one measured below. Launch bounds were removed entirely.

## Results (4K, Qwen2.5-0.5B Q4_K_M, F16 KV, ubatch 64, GPU-control)

**Kernel events** (`--profile cuda`, 5 alternating pairs, prefill kernel time per request):

| | median | range |
|---|---:|---|
| cells-kc | 1.1736 s | 1.1615–1.1791 |
| cells-v2 | 1.0999 s | 1.0859–1.1069 |

**−6.3%**, v2 faster in 5/5, ranges do not overlap. The map predicted about −5%.

**Profiler-off prefill** (7 alternating pairs, idle machine, load average 3.2–4.4 with the benchmark itself running; `prefill-ab-unbounded76-idle/`):

| | median | range |
|---|---:|---|
| cells-kc | 2.442 s | 2.349–2.460 |
| cells-v2 | 2.332 s | 2.303–2.464 |

**−4.5%**, v2 faster in 6/7. The one overlap is v2's pair-7 value of 2.464 s. An earlier 7-pair run under heavy foreign load (IDE indexing, Gradle) pointed the same way (6/7) but is not used as evidence (`prefill-ab-unbounded76-noisy/`).

**Decision.** The plan prefers ≥5% on total prefill, and 3–5% is its "re-measure with 7" band. This *is* the 7-pair measurement. E4 is accepted at −4.5% because:
- the kernel signal is clean (5/5, non-overlapping),
- two independent 7-pair runs agree in direction,
- the change is ~12 lines and bit-exact.

This is a judgment call against a stated preference, not a threshold that was met.

## Final baseline (profiler off, 5 repeats, idle GPU; `e4-final-baseline.json`)

- stock-host 1.342 s (1.329–1.454);
- GPU-control **2.328 s** (2.271–2.396), **1.73x** stock; −3.2% against E2's 2.406 s;
- decode 7.53 tok/s. The decode path is the unchanged staged Q=1 path, so this is run-to-run variance and not an E4 effect;
- hash `a152ed56` on every run.

**Policy-on regression** (`argus-cuda-on`, 3 repeats): 9.456 / 8.976 / 8.922 s, median 8.976 s against E2's 9.178 s. Counters are identical to E2: 12,768 promotions, 0 demotions, 12,768 committed pages.

Milestones: M1 and M2 met. **M3 (< 2.25 s) not met; −0.078 s remains.**

## Correctness

- GPU 7/7 and CPU/context 8 passed + 2 skipped (no quantized GGUF), with `cells-v2` added to every path list.
- After the default flip, the full native suite ran again: 15 passed, 2 skipped.

`ARGUS_KV_ATTENTION_PATH` unset or `cells-v2` selects the new kernel. `cells-kc` remains selectable as the reference.
